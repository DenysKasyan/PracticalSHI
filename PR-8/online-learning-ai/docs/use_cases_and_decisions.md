# Use Cases & Decision Points

## 0. System context (2–4 sentences)

- System name: Інтелектуальна система онлайн-освіти.
- Target users: студенти, викладачі, адміністратори та керівництво навчального закладу.
- Main value: навчання, оцінювання і своєчасна підтримка студента в єдиному середовищі.
- AI component role (1 sentence): визначає індекс навчального ризику і пояснює його складові для попереднього сортування карток викладача.

## A. Use Cases

### UC-01: Записатися на навчальний курс

- Primary actor: Студент.
- Secondary actors: Адміністратор, викладач.
- Trigger: Студент натискає «Записатися».
- Preconditions: Обліковий запис активний. Курс є в каталозі.
- Main flow:
  1) Відкрити картку курсу.
  2) Подати запит.
  3) Перевірити роль, доступ та дублікати [DP-01].
  4) Зберегти членство один раз.
  5) Показати курс у кабінеті.
- Alternative / exception flows:
  - A1) Повторний запит повертає наявне членство.
  - E1) Закритий курс показує причину відмови.
- Output / outcome: Доступ до курсу та підтвердження запису.
- Constraints (NFR): Повтор однакового запиту без дублювання.

### UC-02: Пройти тест і отримати результат

- Primary actor: Студент.
- Secondary actors: Викладач.
- Trigger: Студент починає тест.
- Preconditions: Є доступ до курсу, тест відкрито.
- Main flow:
  1) Відкрити спробу.
  2) Заповнити відповіді.
  3) Надіслати.
  4) Перевірити валідність і тип відповіді [DP-02].
  5) Зберегти результат.
  6) Показати бал або статус перевірки.
- Alternative / exception flows:
  - A1) Відкрита відповідь переходить викладачу.
  - E1) Прострочену спробу відхилено з поясненням.
- Output / outcome: Бал тесту або статус ручної перевірки.
- Constraints (NFR): Аудит спроб і версії ключа оцінювання.

### UC-03: Виявити студента, якому потрібна підтримка

- Primary actor: Викладач.
- Secondary actors: Студент, адміністратор.
- Trigger: Викладач відкриває огляд групи.
- Preconditions: Є права на курс. Для всіх студентів застосовано однаковий контрольний зріз.
- Main flow:
  1) Відкрити огляд.
  2) Отримати зріз ознак.
  3) Перевірити повноту [DP-03].
  4) Обчислити індекс ризику.
  5) Маршрутизувати оцінку [DP-04].
  6) Для черги перевірити контекст і вирішити, чи запропонувати підтримку [DP-05].
  7) Зберегти рішення.
- Alternative / exception flows:
  - A1) Низький індекс оновлює статус моніторингу.
  - E1) Некоректні дані або збій переводять у статус «оцінка недоступна».
- Output / outcome: Картка з індексом, факторами й статусом розгляду для викладача.
- Constraints (NFR): Пояснення складових індексу та аудит людського рішення.

### UC-04: Отримати рекомендацію щодо повторення теми

- Primary actor: Студент.
- Secondary actors: Викладач.
- Trigger: Студент відкриває розділ повторення після тесту.
- Preconditions: Курс містить тематичну розмітку і дозволені матеріали.
- Main flow:
  1) Відкрити результати.
  2) Зіставити помилки з темами.
  3) Перевірити придатність матеріалів [DP-06].
  4) Показати релевантну добірку.
  5) Відкрити вибраний матеріал.
- Alternative / exception flows:
  - A1) За відсутності помилок показано матеріали для закріплення.
  - E1) Без розмітки показано загальний каталог курсу.
- Output / outcome: Посилання на матеріал курсу й причина добору.
- Constraints (NFR): Тільки матеріали, доступні студенту.

### UC-05: Опублікувати навчальний матеріал

- Primary actor: Викладач.
- Secondary actors: Адміністратор, студент.
- Trigger: Викладач натискає «Опублікувати».
- Preconditions: Є чернетка та право редагувати курс.
- Main flow:
  1) Відкрити чернетку.
  2) Перевірити обов’язкові поля.
  3) Зберегти версію.
  4) Підтвердити готовність [DP-07].
  5) Оновити видимість у курсі.
  6) Показати квитанцію.
- Alternative / exception flows:
  - A1) Матеріал лишається чернеткою.
  - E1) Помилкове вкладення блокує публікацію.
- Output / outcome: Опублікована версія або збережена чернетка.
- Constraints (NFR): Автор, час і версія доступні в журналі.

### UC-06: Виправити оцінку за завдання

- Primary actor: Викладач.
- Secondary actors: Студент, адміністратор.
- Trigger: Надходить обґрунтоване звернення або виявлено помилку.
- Preconditions: Результат існує. Викладач має право перевірки.
- Main flow:
  1) Відкрити спробу.
  2) Звірити відповідь із критеріями.
  3) Прийняти рішення [DP-08].
  4) Зберегти причину й версію.
  5) Показати актуальний результат студенту.
- Alternative / exception flows:
  - A1) Оцінку підтверджено без змін.
  - E1) Конфлікт версій вимагає повторно відкрити спробу.
- Output / outcome: Рішення про перегляд та актуальна оцінка.
- Constraints (NFR): Історію змін зберігають із обмеженням доступу.

### UC-07: Сформувати зведення успішності

- Primary actor: Керівник закладу.
- Secondary actors: Викладач, адміністратор.
- Trigger: Керівник задає період і просить звіт.
- Preconditions: Є право на агреговані звіти.
- Main flow:
  1) Вибрати період.
  2) Визначити вибірку курсів.
  3) Перевірити розмір груп [DP-09].
  4) Обчислити дозволені агрегати.
  5) Показати або експортувати зведення.
- Alternative / exception flows:
  - A1) Для малих груп показано лише надгрупу, якщо вона придатна.
  - E1) Порожня вибірка повертає пояснення.
- Output / outcome: Агрегований звіт та ознаки прихованих груп.
- Constraints (NFR): Комірки з n < 5 приховуються. Персональні дані не експортуються.

### UC-08: Змінити роль облікового запису

- Primary actor: Адміністратор.
- Secondary actors: Користувач, відповідальний за доступ.
- Trigger: Надійшла заявка на зміну повноважень.
- Preconditions: Є автентифікований адміністратор та ідентифікатор заявки.
- Main flow:
  1) Відкрити заявку.
  2) Перевірити особу й підставу.
  3) Погодити чи відхилити роль [DP-10].
  4) Оновити політику доступу.
  5) Зафіксувати дію.
  6) Повідомити заявника.
- Alternative / exception flows:
  - A1) Неповна заявка повертається на уточнення.
  - E1) Зміна останнього адміністратора блокується.
- Output / outcome: Підтверджена зміна ролі або відмова з причиною.
- Constraints (NFR): Обов’язковий аудит попередньої і нової ролі.

## D. Flow mapping (1–2)

### Flow for UC-03

1) Викладач відкриває огляд групи. Система збирає зріз на контрольну дату.
2) [DP-03] Перевіряються чотири ознаки. Якщо зріз непридатний, картка отримує статус «оцінка недоступна» і причину. Якщо придатний, компонент повертає індекс та його складові.
3) [DP-04] Індекс <45 оновлює статус моніторингу. Індекс 45–<60 створює звичайний запис на огляд, ≥60 — пріоритетний. За збою формується запис без оцінки для ручного перегляду.
4) [DP-05] Викладач перевіряє факти, обирає дію щодо підтримки та зберігає обґрунтування.

### Flow for UC-02

1) Студент надсилає спробу тесту.
2) [DP-02] Система перевіряє строк, формат і ключ. Валідна закрита спроба оцінюється за ключем, відкрита відповідь передається викладачу, невалідна спроба відхиляється.
3) Студент отримує бал, статус ручної перевірки або причину відмови.
